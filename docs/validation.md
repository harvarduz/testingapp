# Verified release

The account and curriculum update was validated on 13 October 2026 with Node.js 24, Chromium and the compiled production frontend. The supplied Bloom Material Expressive reference remains the visual foundation: four tonal palettes, light/dark modes, self-hosted Google Sans Flex/Roboto, a collapsible rail, neutral information surfaces, outlined secondary actions, and filled primary actions. Google blue uses #0b57d0 in light mode and #a8c7fa in dark mode.

Home and the app share one account menu. Names and email come from the real session; repeated account and sync banners have been removed. Sign in opens login, Create account opens registration, and each form focuses its first field. Menus support keyboard navigation, dismiss predictably, preserve focus, and fit 320/390/1366 px. Failed saving offers retry; failed logout preserves the account with recovery feedback. Logout protects unsaved creator work and clears private editor state after success. A delayed login response accepts the account without closing a newer dialog. Review-to-account navigation exposed a queued scroll event that dismissed the menu; dismissal now requires an actual page or anchor movement. The avatar no longer inherits the old hover colour.

All 20 starter courses were expanded to at least five lessons: 101 lessons and 218 additional practice questions across 18 subjects. Each lesson includes goals, a stepped worked example, a common mistake and explained exercises. The original 61 lessons keep their positions and questions; 40 application lessons are appended. Practice history, completion and rewards remain separate, and existing saved records retain their meaning without a schema migration.

The production build and the suites below verify the final platform. A dedicated account/curriculum suite exercises 60 lesson flows across every course, including the first original lesson and both application lessons. It verifies wrong-answer retry, double-activation protection, zero premature completion/coins, account recovery and private-editor logout. Automated accessibility checks cover 244 light/dark page, palette, selection and account-menu states. Visual review includes actual 320/390 px menus, desktop/mobile lessons and light/dark screens.

Build first, then run the interaction suites; each starts an isolated server and removes its temporary accounts and drafts:

```sh
npm run build
python tests/select_smoke.py
python tests/hover_smoke.py
python tests/navigation_smoke.py
python tests/platform_ux_smoke.py
```

`npm run build` passed. Layout checks cover 320, 390, 768, 800, 1024, and 1366 px widths, including short mobile and desktop heights. Intermediate tablet review found a goal-card overflow inherited from the old horizontal grid; the desktop goal card now uses a vertical layout, while the mobile card uses a bounded two-column grid. The sidebar was reproduced at a 600 px viewport with 812 px of content and no scrolling. It now scrolls independently, collapses to a 96 px icon rail, remembers its browser preference, and expands into a full mobile drawer. Mobile focus trapping, Escape, restored focus, and navigation were tested.

The catalog has 20 introductory courses and 101 lessons across 18 subjects. Every lesson includes at least two learning goals, three worked steps, a common mistake and two transfer questions; the 16 previously enriched lessons retain three transfer questions each. The total is 218 additional practice questions. The new application lessons address unit pricing, recipe ratios, debugging, fair investigations, data comparisons, source provenance, usable forms, household finance and other practical decisions. Seven study paths cover the catalog with suggested course order and outcomes. They recommend rather than lock courses.

Opening a lesson, its check, or the idea again resets the dialog scroll and focuses it, keeping the title visible after using a bottom-of-page action. Worked examples reveal one step at a time with Previous/Next and Review controls. Inline exercises explain correct and incorrect answers, allow retries, and feed practice history. Their completion does not finish the lesson or award a session reward. The existing lesson check records course completion, and targeted sessions retain their daily coin rules. Newly authored answer choices rotate deterministically to avoid a fixed correct-answer position. Content/publication validation covers all 101 lessons; browser testing covers 60 original/application lesson flows across all 20 courses.

Learning Lab requires meaningful interaction: the fraction challenge accepts equivalent models using at least eight pieces; the budget protects minimum spending on essential needs as well as savings; and the algorithm locks a prediction before the student traces each value. Wrong predictions do not earn lab coins. Both summation and maximum traces work on bounded whole-number inputs. Completed labs persist across devices and contribute once to daily activity. Repeated completion does not award coins again.

Practice chooses missed questions before unattempted questions and older correct answers. Sessions explain answers and recommend the lessons behind mistakes. The latest 500 attempt records support recent-answer statistics; course completion records remain separate. A real editor-created course with goals, worked steps, and practice was published and used by another student browser.

Curio coins are derived from saved learning records: 25 per newly completed lesson, 15 per daily challenge, and 20 for the first successful practice session per day, and 30 for each completed lab once. At least one answer must be correct to earn a practice reward. Tests repeat sessions, merge two devices, and revisit lessons to verify that rewards and course completions are not duplicated. Coins have no cash value or purchase/withdrawal system. They are learning motivation, not an accredited assessment or financial balance.

Paths, attempts, lab completions, reward-earning days, notes, and bookmarks were verified across independent browser contexts and production container replacement. Existing course JSON without extension fields and earlier progress records remain compatible. No SQLite schema migration is required for this release; retained data uses the existing account progress store.

The supplied reference was inspected from TLS-verified downloaded assets in a local browser. Its actual purple primary (#65558f) and surface (#fdf7ff), Tonal Spot generation, fonts, rail proportions, card outlines, and shapes were checked against Curio. Palette state persists per browser, including navigation/reload; unavailable storage is explained. The appearance picker uses the existing modal focus trap, and both mobile menus restore focus to a visible opener. Material Color Utilities is bundled separately for cache reuse. Font licences accompany the self-hosted assets.

The requested blue update keeps the reference's shapes and type while applying Google blue primary roles to its generated foundation. A versioned browser preference migrates the earlier automatically persisted purple default once; explicit new choices survive reload. Native button activation stays intact: Space acts on release, Enter acts once, and actual mobile taps still complete the homepage exercise. Ripples start at the pointer or keyboard centre, remain bounded, fade out, and remove their temporary DOM nodes. A drag, scroll, pointer cancellation, loss of focus, or hidden window releases the press state. Disabled buttons remain inert, and reduced motion omits ripple elements. Primary actions have a 48 px height and a 3 px keyboard outline. Ripples replace rather than stack over the hover/focus layer, preserving contrast through the press. A modal focus-restoration race was fixed so Escape followed immediately by the search shortcut does not move focus back to the opener.

Selection behavior uses the pinned MIT-licensed `@radix-ui/react-select` 2.2.6 dependency, with shared Material presentation and a separate UI vendor bundle. Menus stay inside a dialog's focus boundary, and Escape closes a menu before its parent dialog. While a menu is open, controls outside it are inert; closing restores their previous boundaries and returns focus to the trigger. Keyboard options use the current Material primary colour for their inset focus ring. Form options preserve string identifiers and convert quiz answers and daily goals back to numbers. The preference footer's legacy 9 px forced colour was removed after reproducing a 1.89:1 contrast failure; the updated footer passes light/dark axe checks. The themed discard confirmation preserves unsaved values on cancel, captures a requested search before deferring it, and resumes direct hash navigation only after acceptance. Focus returns to the visible mobile menu button even when a route change occurs while its drawer is open.

Visual screenshots were reviewed. Colour distinguishes learning goals, worked steps, correct answers, useful mistakes, and rewards. Hover uses one state layer without shifting course artwork, titles, or selected controls. Reduced-motion CSS disables decorative effects; programmatic navigation also uses immediate scrolling when reduced motion is requested. The main accessibility, palette, and opened-menu suites found zero automated violations across 244 light/dark states. These checks supplement manual review and do not certify complete WCAG compliance.
